# Architectural & Experimental Decisions (`DECISIONS.md`)

1. **Workspace Layout**: The workspace `/home/ashish/genai_project` serves directly as the `stopwise/` project root (`configs/`, `data/`, `src/`, `runs/`, `checkpoints/`, `tests/`, `scripts/`, `results/`, `REPORT.md`, `README.md`, `PROGRESS.md`, `DECISIONS.md`). A symbolic link `stopwise -> .` is also created in the workspace root so any path referencing `stopwise/...` or `./...` resolves identically.
2. **Base Model**: We use `Qwen/Qwen2.5-3B-Instruct` as the primary base model with LoRA (`r=16, alpha=32`) via PEFT on the single NVIDIA RTX 6000 Ada (48 GB VRAM).
3. **RL Framework (Methods B & C)**: We implement a clean, self-contained, unit-tested PyTorch/PEFT GRPO trainer (`src/train/grpo.py`) alongside TRL compatibility, supporting exact token-level masking of `<result>...</result>` tool outputs, group-normalized advantages ($G=8$), KL penalty ($\beta = 0.01$) against the reference model, and the exact cost-aware reward function. This guarantees 100% adherence to the `<result>` span masking and multi-step agent trajectory rollout requirements.
4. **Readiness Representation**: We implement the parsed text readiness score (`<ready>0.xx</ready>`) as primary, and also provide the linear readiness head module (`src/agent/readiness_head.py`) on hidden states for auxiliary calibration and comparison.
5. **Passage Corpus & Hybrid Retriever**: Following Section 3.2 and Fallback #3, we construct a dense + sparse Wikipedia passage index combining all gold supporting passages from HotpotQA, 2WikiMultiHopQA, and MuSiQue splits plus random distractor Wikipedia passages (~100-word chunks), indexed with both `rank_bm25` (sparse BM25) and `FAISS` (`BAAI/bge-small-en-v1.5` embeddings), followed by cross-encoder re-ranking (`BAAI/bge-reranker-base`).
6. **Dataset Split Sizes & Resumability**: To keep full multi-step run collection, 5-sample per-step cut-off labelling, SFT, GRPO ($\lambda \in \{0, 0.1, 0.3, 0.6\}$), and evaluations E1–E10 completing cleanly with real LLM calls on a single GPU, we use fixed-seed splits configured in `configs/default.yaml` (with smoke-test slice flags and full benchmark splits cached in `data/processed/`). All test sets are strictly disjoint from training sets and verified by automated leakage tests.
